## Overview

Use `siclaw local` for interactive investigations and configuration in the Web UI. Use `siclaw --prompt "..."` for a single diagnostic invocation that prints its answer and exits.

When started from the same working directory, the CLI can reuse the local Portal's providers, agents, skills, knowledge, MCP servers, and credentials. Configuration changes happen in the Web UI and apply to the next invocation.

## Start a Diagnostic Run

```bash
# Terminal A — local Web UI
cd ~/siclaw-work
siclaw local

# Terminal B — same workspace, after configuring a model and agent
cd ~/siclaw-work
siclaw agents
siclaw --agent sre-oncall --prompt "Why is the API pod Pending?"
siclaw --agent sre-oncall --continue --prompt "Check recent events"
```

Replace `sre-oncall` with a name returned by `siclaw agents`. With one configured agent, selection is automatic. With multiple agents, pass `--agent`; the CLI exits with a list of names if selection is ambiguous.

`--prompt` is required for diagnostic execution, including with `--continue`. Bare `siclaw` prints help. The CLI has no interactive setup or slash commands. Use the Web UI to inspect and edit resources.

## Snapshot Lifecycle

On startup, the CLI looks for `.siclaw/local-secrets.json` in the working directory and probes the local Portal. It then:

1. Uses the dedicated `cliSnapshotSecret` to authenticate snapshot requests.
2. Fetches `GET /api/v1/cli-snapshot?agent=<name>` directly for an explicit agent; otherwise discovers available agents and selects deterministically.
3. Materializes skills, knowledge, and credentials under a private `.siclaw/.portal-snapshot/run-<random>/` directory, including empty resource sets.
4. Runs the shared agent engine with those resources.
5. Cleans the snapshot on normal exit, startup failure, `SIGINT`, or `SIGTERM`.

Without a selected agent, an unavailable Portal allows standalone execution using `.siclaw/config/settings.json` and local resources. Once an agent is selected (explicitly or automatically), its snapshot must load successfully or the CLI exits nonzero. It never silently substitutes another configuration. Missing model configuration produces an error and exits; it never opens a setup prompt. `siclaw agents` requires Portal and exits nonzero if it is unavailable.

The snapshot endpoint is enabled only by `siclaw local`, accepts loopback requests only, and requires `X-Siclaw-Cli-Snapshot-Secret`. The dedicated secret does not grant Portal admin API access. Production Portal keeps this endpoint disabled.

## Workspace and Ports

Both processes must use the same working directory and its local secrets. The CLI reads configuration over HTTP; it does not open Portal's database directly.

For a custom Portal port:

```bash
PORTAL_PORT=8080 siclaw local
SICLAW_PORTAL_PORT=8080 siclaw --agent sre-oncall --prompt "Check cluster health"
```

The local server also needs free Runtime and internal ports (3001 and 3002 by default). Set `SICLAW_PORT` and `SICLAW_INTERNAL_PORT` when running multiple local servers.

## Filesystem Layout

```text
.siclaw/
├── config/settings.json       standalone CLI configuration
├── credentials/               standalone credential store
├── .portal-snapshot/
│   └── run-<random>/          private to one invocation; removed on exit
│       ├── skills/
│       ├── knowledge/
│       └── credentials/
├── local-secrets.json          generated by siclaw local, mode 0600
├── data/portal.db              local Portal database
└── user-data/memory/           local investigation memory
```

Concurrent invocations use separate snapshot roots and clean only their own files. Empty Portal bindings remain empty rather than inheriting standalone resources. Portal snapshots do not replace the standalone configuration files. Investigation memory remains a separate persistence domain from Portal configuration.

## Choose an Entry Point

| Need | Entry point |
|---|---|
| Interactive diagnosis and resource configuration | `siclaw local`, then open the Web UI |
| One diagnostic run from a shell or script | `siclaw --prompt "..."` |
| Reuse a specific local agent's bindings | `siclaw --agent <name> --prompt "..."` |
| Remote automation against a deployed team instance | [External API](/features/deep-investigation#external-api) |
| Production team deployment | [Kubernetes](/install/kubernetes) |
