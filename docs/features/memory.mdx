Memory is opt-in (`SICLAW_MEMORY_ENABLED=true`, or Helm
`runtime.memory.enabled`). It uses the Agent's configured model and needs no
embedding provider, vector database or FTS index.

## Learning useful evidence

After a completed turn is saved, AgentBox reviews unreviewed source records in the
background. It can retain stable preferences, project conventions, corrections,
and useful task experience. Exact quotes retain their roles and provenance;
failed attempts, proposals and uncertain outcomes remain distinguishable.
An assistant's success claim or a successful tool invocation does not prove that
a repair worked. Trivial questions, routine inventory and temporary task requests
should produce no memory.

The host selects committed snapshots and checks source access, learning leases,
quotes and generations before publishing. Transient failures retry while the box
is resident. Restarted boxes resume eligible learning without another question.
Learning never writes skills, executes scripts or restores historical permission.

## Recall without filling the context

Use `memory_search` for relevant prior decisions and `memory_get` for precise
source windows. `memory_catalog` provides at most eight navigation entries when
the topic is unclear. Historical evidence must be verified against current facts.
Memory is skipped for self-contained calculations, translations and questions
already answered by the current conversation.

Search/read/catalog share response, turn and context budgets. Compaction clears
only disposable recall bookkeeping. Cited sources record usage automatically;
`memory_feedback` flags incorrect or irrelevant evidence. Repeated use is a small
ranking signal, not proof.

## Remember, correct and forget

An explicit user request can use `memory_update` with an exact quote from the
current user message. Remember/correct requests are accepted for background
review. Forget targets an existing returned memory path and takes effect
immediately; a tombstone prevents stale learning from bringing it back. An
explicit later remember request can replace that tombstone.

Reading memory uses the `search_memory` capability. Explicit updates and feedback
use the separate `manage_memory` capability. An existing read-only custom Agent
selection does not acquire update permission automatically.

## Storage and retention

Remote deployments store source bodies and learning batches in versioned object
storage, and ownership, topics, leases and receipts in the host's metadata store.
All participating Runtimes must use the same bound backend for an existing
personal space. Local/CLI uses per-user transactional SQLite under
`memory-v2/<owner hash>/memory-v2.db`; local development is not a substitute for
production operating-system isolation.

Recall expires at most 90 days after the source event. Learning is capped at 64
batches per user per UTC day, with smaller batches after repeated failures and a
one-day cooldown after eight failed attempts. Each batch has at most 24 primary source
fragments and eight adjacent read-only context fragments, sharing 32 KiB of input. These limits bound memory cost independently of
the foreground task.

Deleting learned memory does not erase conversations, checkpoint files or
retained object versions. Old `.memory.db` investigation rows remain exportable;
the retired database is not opened as a recall backend or deleted as a cache.
