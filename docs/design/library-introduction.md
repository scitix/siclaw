# Versioned library introductions

A consuming agent needs to understand a Wiki's purpose, topic relationships,
applicability and reading order before treating individual search hits as enough
evidence. Every completed compilation generates a full library introduction.
The one-line summary is also the existing consumer-domain subtitle.

## Artifact contract

`candidate/.library-introduction.json` is generated by `report_domain`, shipped
unchanged at the package root, and retained with that immutable Wiki version.
The model supplies `domain` plus an `introduction` object; the tool supplies
`schema_version` and copies `domain` into `summary`.

```json
{
  "schema_version": 1,
  "summary": "Device X operation and recovery",
  "overview": "The library explains the documented operating model and recovery procedures.",
  "knowledge_structure": "Concepts establish the operating model; procedures apply it to recovery.",
  "typical_questions": ["How do I recover Device X?"],
  "scope": "Applies to the documented release. Confirm current conditions before using a procedure.",
  "reading_guide": [
    {"path": "recovery.md", "reason": "Start with prerequisites and exceptions."}
  ]
}
```

All text fields are required and nonempty. The summary is a single normalized
line of at most 100 Unicode characters. Questions and reading entries each have
1–12 items. Paths are existing, file-relative Markdown paths inside the same
Wiki, without symlinks, hidden components, fragments or query strings. The
complete serialized UTF-8 artifact is at most 48 KiB. Invalid or over-budget
input is rejected for correction, never silently truncated.

Write a few substantive paragraphs based on the complete finished catalog and
relevant topic overviews. Explain relationships and actual answerable questions,
including inherited topics, conditions and known gaps. Incremental updates
reassess the whole library after scoped page changes; the latest batch alone is
not the source for the introduction. The existing full-catalog refresh action
can generate or update it without recompiling source pages. Owners can request
corrections through the authoring conversation and inspect the draft before
publishing.

## Consumption and publication

The introduction is navigation metadata, not evidence that a factual answer or
original-source citation is valid. It is a JSON sidecar, so content-page search
and citation eligibility do not treat it as an answer page. The aggregate
catalog shows every mounted library's summary, bounded overview preview,
sample questions and full-introduction path. Previews explicitly remain samples;
they never replace the full introduction or exclude a library from search. A
single-library context exposes the same reading entry. The consumer reads the
introduction, then follows its guide and relevant Wiki links. Scope descriptions
prioritize exploration; they must not exclude other mounted libraries from a
cross-library search.

The publisher validates the sidecar against the exact package file set and,
for authoring publication, the exact attempt's domain. Draft and published
introductions remain separate. Activation and rollback select the introduction
already inside that version's package. Imported packages may include this
optional sidecar; its summary is authoritative for that package. Older packages
remain usable and display an honest missing-introduction state.

Human-facing lists keep their short subtitle. Detail and settings views load
the complete introduction only when expanded, identify published versus draft
content, and preserve all sections. Published metadata is scoped like the
organization's bindable catalog; draft reading remains owner/collaborator-only.

## Acceptance

- Generate, synchronize and publish the same sidecar bytes with the Wiki.
- Reject missing guide targets, escaped paths, malformed data and oversize
  introductions; distinguish invalid metadata from legacy absence.
- A draft edit must not change a published introduction; rollback restores the
  corresponding old introduction and summary.
- Every mounted library remains visible; no truncation of the complete library
  list or use of introduction metadata as answer evidence.
- Test normal-agent routing, cross-page conditions and complete evidence
  coverage separately from parser and publication conformance.
